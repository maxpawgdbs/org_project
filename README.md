# Telegram-бот маршрута по Москве

В `content/route.json` загружена книга автора `Moskva_v_dvizhenii_obrazec_01.xlsx`: реальные название и общие тексты, план 10 точек, координаты, переходы и источники. Полная карточка и ссылка на фотографию пока есть только у остановки № 1. Карточки № 2–10 содержат сведения из авторского плана и явную пометку о неполноте. Пять вопросов викторины, имена авторов проекта и ссылка на интерактивную общую карту пока остаются техническими заглушками. Приложенная обзорная карта показывается как изображение.

## Что уже работает

- `/start`, главное меню, список остановок и навигация по порядку или из списка;
- карточка с фотографией, полным текстом, адресом, картой точки, источниками и переходом;
- сохранение последней остановки отдельно для каждого Telegram ID в SQLite;
- автоматический итоговый текст после последней остановки и викторина из пяти вопросов;
- переход к главному меню при неизвестном сообщении, повторные нажатия без повторного начисления баллов;
- продолжение после перезапуска, работа без телефона, имени и геолокации пользователя.

Бот использует Python 3.10+ и стандартную библиотеку. `requirements.txt` намеренно пуст. Для создания QR-кода нужен отдельный `requirements-tools.txt`.

## Материалы

Формат работы бота: UTF-8 файл [route.json](content/route.json) и фотографии в `content/photos/`. Подробное описание полей — в [content-format.md](docs/content-format.md). Каждый объект имеет постоянный `id`; порядок задаёт `order`, поэтому перестановка не требует изменения кода. Фото можно указать относительным путём (`photos/01.jpg`) или ссылкой `photo_url`. Если файл отсутствует, бот попробует ссылку, а затем покажет текст без фото.

Из полученной книги JSON создан командой `python -m scripts.import_materials Moskva_v_dvizhenii_obrazec_01.xlsx --map-image tg_image_2290692622.png`. Повторный импорт обновит карточки из книги и сохранит существующие вопросы, авторов и ссылку на общую карту из JSON. Редактировать JSON вручную тоже можно. После повторного импорта проверьте результат и список источников.

После получения материалов:

1. Получить у автора полные карточки № 2–10, соответствующие фотографии, пять вопросов с ответами и пояснениями, имена авторов проекта и ссылку на общую интерактивную карту. Заменить все строки `[ТЕХНИЧЕСКАЯ ЗАГЛУШКА]`.
2. Установить `is_placeholder` в `false`.
3. Выполнить `python -m scripts.validate_content content/route.json`.
4. Перезапустить процесс бота. База `data/progress.sqlite3` сохраняется; копируйте её перед обновлением. Если ID остановки удалён, «Продолжить маршрут» откроет первую остановку.

Файл `content/photos/01.jpg` не был приложен. Для первой остановки подключена переданная автором прямая ссылка на оригинал Wikimedia Commons; при недоступности ссылки карточка всё равно отправит текст. Локальный файл предпочтителен для демонстрации, его можно добавить под указанным в JSON именем. Книга указывает для этого фото автора Kotofey2016 / Википедия и лицензию CC BY-SA 4.0; подпись и ссылки включены в карточку и источники. [Страница фотографии](https://commons.wikimedia.org/wiki/File:%D0%91%D0%B5%D0%BB%D0%BE%D1%80%D1%83%D1%81%D1%81%D0%BA%D0%B8%D0%B9_%D0%B2%D0%BE%D0%BA%D0%B7%D0%B0%D0%BB._%D0%B4%D0%B5%D0%BA%D0%B0%D0%B1%D1%80%D1%8C_2024.jpg).

## Локальный запуск

1. Создать бота через BotFather и получить токен. Открыть локальный файл `.env` в корне проекта и вставить токен после `TELEGRAM_BOT_TOKEN=`. В этот же файл можно вписать публичный `BOT_USERNAME` для QR-кода. `.env` загружается ботом автоматически и исключён из Git.
2. Пока в маршруте есть заглушки, оставить в `.env` строку `ALLOW_PLACEHOLDERS=1`.
3. Из корня проекта запустить `python -m route_bot.bot`.
4. Открыть `https://t.me/<имя_бота>` и отправить `/start`.

Если не хотите сохранять токен в файле, можно задать переменную только для текущего окна PowerShell:

```powershell
$secureToken = Read-Host 'Токен BotFather' -AsSecureString
$env:TELEGRAM_BOT_TOKEN = [System.Net.NetworkCredential]::new('', $secureToken).Password
$env:ALLOW_PLACEHOLDERS = '1'
python -m route_bot.bot
```

Для настоящих материалов удалите из `.env` строку `ALLOW_PLACEHOLDERS=1` или замените её на `ALLOW_PLACEHOLDERS=0`. Бот читает JSON при запуске, поэтому после изменения материалов процесс нужно перезапустить. Переменные, уже заданные в системе или на сервере, имеют приоритет над `.env`.

Опциональные переменные: `ROUTE_FILE`, `DATABASE_FILE`, `LOG_FILE`. По умолчанию используются `content/route.json`, `data/progress.sqlite3`, `data/bot.log`. Папка `data/` создаётся автоматически. Файл базы и журнал нельзя публиковать. Для штатного перезапуска остановите процесс и запустите его снова; прогресс останется. Одновременно должен работать только **один** процесс с этим токеном и базой.

Локальная проверка без токена: `python -m unittest discover -s tests -v` и `python -m scripts.validate_content --allow-placeholders`.

## Работа во время защиты

Для постоянной работы нужен сервер или другая согласованная с командой площадка, где процесс работает без компьютера выступающего и хранится SQLite. Стоимость и выбор площадки нужно согласовать **до размещения**. В [route-bot.service.example](deploy/route-bot.service.example) есть пример службы Linux `systemd`; замените пути и пользователя. Секреты храните во внешнем `EnvironmentFile` с доступом только администратору. После копирования кода и материалов установите Python 3.10+, проверьте JSON, запустите службу и проверьте её после перезапуска сервера.

QR-код создаётся **после появления публичного username**. Установите `python -m pip install -r requirements-tools.txt`, впишите `BOT_USERNAME` в `.env` и запустите `python -m scripts.create_qr`. Получатся `deliverables/bot_qr.png` и `deliverables/bot_link.txt`. Токен для QR не нужен.
