# Telegram-бот маршрута по Москве

В `content/route.json` загружена книга автора `Moskva_v_dvizhenii_obrazec_01.xlsx`: название, общие тексты, план 10 точек, координаты, переходы и источники. Первая карточка взята из книги; карточки № 2–10 и викторина составлены по авторскому плану. Для каждой точки загружена фотография Wikimedia Commons с подписью, лицензией и ссылкой на страницу файла. Общая интерактивная карта подключена по переданной ссылке; обзорная карта показывается изображением при `/start`. Исторические тексты и вопросы, подготовленные по плану, следует согласовать с автором перед защитой.

## Что уже работает

- `/start` с обзорной картой и приветствием, главное меню, список остановок и навигация по порядку или из списка;
- карточка: заголовок и описание в подписи к фотографии, затем задание, адрес, карта точки, источники и переход;
- сохранение последней остановки отдельно для каждого Telegram ID в SQLite;
- автоматический итоговый текст после последней остановки и викторина из пяти вопросов;
- переход к главному меню при неизвестном сообщении, повторные нажатия без повторного начисления баллов;
- продолжение после перезапуска, работа без телефона, имени и геолокации пользователя.

Бот использует Python 3.10+ и стандартную библиотеку. `requirements.txt` намеренно пуст. Для создания QR-кода нужен отдельный `requirements-tools.txt`.

## Материалы

Формат работы бота: UTF-8 файл [route.json](content/route.json) и фотографии в `content/photos/`. Подробное описание полей — в [content-format.md](docs/content-format.md). Каждый объект имеет постоянный `id`; порядок задаёт `order`, поэтому перестановка не требует изменения кода. Фото можно указать относительным путём (`photos/01.jpg`) или ссылкой `photo_url`. Если файл отсутствует, бот попробует ссылку, а затем покажет текст без фото.

Подпись к фотографии ограничена Telegram 1024 символами UTF-16. Текущие описания всех 10 точек помещаются целиком; описание № 1 сокращено для этого формата и требует согласования с автором. Если позже добавить более длинный текст, бот отправит продолжение отдельным сообщением без обрезки.

Из полученной книги JSON создан командой `python -m scripts.import_materials Moskva_v_dvizhenii_obrazec_01.xlsx --map-image tg_image_2290692622.png`. Повторный импорт сохранит готовые карточки, пока в книге для них есть только план; полная карточка в обновлённой книге заменит текущую. Вопросы, авторов и ссылку на общую карту импорт также сохраняет. Редактировать JSON вручную можно. После импорта проверьте карточки и источники.

Для обновления авторских материалов:

1. Согласовать подготовленные карточки № 2–10 и пять вопросов с автором. Заменить тексты в `content/route.json` или внести полные карточки в книгу и повторить импорт. Поле `authors` сейчас содержит общее название команды; при необходимости укажите имена.
2. При замене фотографии положить новый файл в `content/photos/`, обновить `photo`, `photo_credit` и ссылки в `sources`.
3. Выполнить `python -m scripts.validate_content content/route.json`.
4. Перезапустить процесс бота. База `data/progress.sqlite3` сохраняется; копируйте её перед обновлением. Если ID остановки удалён, «Продолжить маршрут» откроет первую остановку.

Локальные изображения `01.jpg`–`10.jpg` загружены в размере до 1280 пикселей. Их происхождение указано в [photo_sources.json](content/photo_sources.json). Для повторной загрузки можно запустить `python -m scripts.download_commons_photos`, затем `python -m scripts.apply_photo_sources`; понадобится доступ к Wikimedia Commons. Фото первой остановки указано автором в книге, остальные подобраны для этих точек. Фотографии в карточках подписаны, а ссылки на лицензии доступны в источниках.

## Локальный запуск

1. Создать бота через BotFather и получить токен. Открыть локальный файл `.env` в корне проекта и вставить токен после `TELEGRAM_BOT_TOKEN=`. В этот же файл можно вписать публичный `BOT_USERNAME` для QR-кода. `.env` загружается ботом автоматически и исключён из Git.
2. Из корня проекта запустить `python -m route_bot.bot`.
3. Открыть [@orgproject123_bot](https://t.me/orgproject123_bot) и отправить `/start`.

Если не хотите сохранять токен в файле, можно задать переменную только для текущего окна PowerShell:

```powershell
$secureToken = Read-Host 'Токен BotFather' -AsSecureString
$env:TELEGRAM_BOT_TOKEN = [System.Net.NetworkCredential]::new('', $secureToken).Password
python -m route_bot.bot
```

Бот читает JSON при запуске, поэтому после изменения материалов процесс нужно перезапустить. Переменные, уже заданные в системе или на сервере, имеют приоритет над `.env`.

Опциональные переменные: `ROUTE_FILE`, `DATABASE_FILE`, `LOG_FILE`. По умолчанию используются `content/route.json`, `data/progress.sqlite3`, `data/bot.log`. Папка `data/` создаётся автоматически. Файл базы и журнал нельзя публиковать. Для штатного перезапуска остановите процесс и запустите его снова; прогресс останется. Одновременно должен работать только **один** процесс с этим токеном и базой.

Локальная проверка без токена: `python -m unittest discover -s tests -v` и `python -m scripts.validate_content`.

## Работа во время защиты

Для постоянной работы нужен сервер или другая согласованная с командой площадка, где процесс работает без компьютера выступающего и хранится SQLite. Стоимость и выбор площадки нужно согласовать **до размещения**. В [route-bot.service.example](deploy/route-bot.service.example) есть пример службы Linux `systemd`; замените пути и пользователя. Секреты храните во внешнем `EnvironmentFile` с доступом только администратору. После копирования кода и материалов установите Python 3.10+, проверьте JSON, запустите службу и проверьте её после перезапуска сервера.

Публичное имя бота — `@orgproject123_bot`. Готовые [QR-код](deliverables/bot_qr.png) и [ссылка](deliverables/bot_link.txt) находятся в `deliverables/`. Для повторного создания установите `python -m pip install -r requirements-tools.txt`, задайте `BOT_USERNAME=orgproject123_bot` в `.env` или окружении и запустите `python -m scripts.create_qr`. Токен для QR не нужен.
